# podnet hard problems: research results

This page summarizes the current answers to all 32 items (`H-01` to `H-32`) in `docs/research/podnet/hard-problems.md`. The initial study evaluated `podnet` at `177336b` (`v0.4.0-beta.17`) against `podcrates` `a44b185` (`v0.78.1`); status below is updated through **2026-11-27** (`podnet` `v0.4.0-beta.21`+ on `main`, `podcrates` `v0.86.0`).

## Summary of all 32 items

| Item | Old grade | Current status | Answer |
| --- | --- | --- | --- |
| H-01 | very hard | likely impossible (full fidelity), partial route | `SECCOMP_IOCTL_NOTIF_ADDFD` installs a kernel socket with true `AF_INET` names. Exact peer names still require either binding the destination port or writing program memory (`CLONE_NEWUSER` plus `process_vm_writev`); neither holds on hosts that block both. |
| H-02 | likely impossible | fixed (advisory hold) | Landlock ABI 6 enforces an outbound TCP port allow-list and closes inherited sockets, but ignores destination addresses, UDP below ABI 10, unix, netlink, vsock, and unbound `listen(2)`. Refusing `listen` on `Sock::Kernel` with `EPERM` closes the wildcard inbound door in `podnet-netns` (T-507). The hold stays advisory. |
| H-03 | likely impossible | unchanged | A static musl binary cannot resolve when UDP sockets are refused. Bind-mounting a merged `/etc/hosts` in the mount namespace works for known names; a seccomp supervisor can also interpose `/etc/hosts` from memory. `AI_ADDRCONFIG` still fails when UDP is denied. |
| H-04 | hard | fixed (IPv4 UDP) | Oversize UDP datagrams above 1472 bytes received false ICMP port unreachable from smoltcp. Reassembling IPv4 fragments in `crates/podnet-netns/src/netns/udpflow.rs` raises `NETNS_UDP_LIMIT` to `65507` bytes with bounded sets (64), pieces (1024), 30 s idle reap, and overlap drops (T-508). ICMP through SOCKS5 remains unsupported by SOCKS5. |
| H-05 | likely impossible (shim) | fixed (prefix isolation) | Static binaries ignore `LD_PRELOAD`; `io_uring` and `/proc/net` require `netns`. Per-run unique `PODNET_VNET_PREFIX` values (capped at 59 bytes, validated before build with exit 64, unconditional stderr warning in C shim) prevent abstract-name collisions between two shims in one network namespace (T-509). |
| H-06 | hard | documented guarantee | `pod-netstack` already provides counted loss (`udp_rx_dropped`, `udp_tx_dropped`, `udp_oversize`) with a 128-datagram capacity (64 backlog + 64 app channel). The guarantee is counted loss, not zero loss. |
| H-07 | very hard | shipped behind `sidecar` | Unprivileged `ip mptcp endpoint add` returns `EPERM`, and MPTCP cannot cross a CONNECT proxy. Userspace per-flow link bonding is shipped behind `--features sidecar` (`podnet sidecar bond`). |
| H-08 | very hard | hard (policy-bound) | A 3-line `ring` patch builds all 8 static musl targets, but adds 134 lockfile packages and trips `cargo deny` on `chrono`, `paste`, and `dyn-eq`. Remaining blockers are dependency policy. |
| H-09 | hard | measured and fixed (T-247) | Live measurement of NetBird `v0.84.0` netstack mode against self-hosted `netbird-server` on a proxy-only host (`docs/reports/netbird-netstack-2026-11-27.md`) confirmed `podnet pod` + `NB_RELAY_TRANSPORT=ws` works; `crates/podnet-netns/src/upstream.rs` now expands `netbird:[PORT]` to `127.0.0.1:PORT`. |
| H-10 | likely impossible (direct) | works (direct MASQUE and edge via WARP) | Direct MASQUE over TCP 443 through an HTTP CONNECT proxy works with an anonymous WARP device (DNS, TCP, HTTPS carried). A paired `quic+warp` edge run verified `HTTP 200` and served a visitor `HTTP/2 200`. Direct TCP 7844 remains blocked by allowlist-only proxies, and TLS-terminating proxies still break the MASQUE pin. |
| H-11 | hard | measured; handed to `podcrates` (COORD-144) | `cloudflared` uses 1 HA connection for quick tunnels as a client policy. Live direct + `quic+warp` measurements (T-488) recorded 0% HTTP 530; `pod-cloudflare` `ha_connections` alignment and `pod-warp` idle reset detection are handed off in COORD-144 (`#802`). |
| H-12 | very hard | hard (stand-in), very hard (faithful edge) | The tunnel client already reaches a stand-in and `pod-cloudflare` is unfrozen. One server module with ALPN `argotunnel` closes the stand-in gap. |
| H-13 | very hard | **solved (T-002 / `#140`)** | Hermetic live capture of official `cloudflare-warp` `2026.8.2115.0` (`scripts/capture-rig/`, `docs/reports/warp-client-capture-2026-11-27.md`) proved the L4 door (`consumer-masque-proxy.cloudflareclient.com`) requires a Stream 0 `CONNECT :protocol cf-connect-ip :scheme http :authority cloudflareaccess.com :path /` session bootstrap followed by per-flow plain `CONNECT` with IP-literal `:authority`. `src/warp/l4.rs` implements this with DoH-over-L4 IP resolution and verified live `warp=on` + 20 MB `HTTP 200` download. |
| H-14 | likely impossible now | **solved (T-004 / `#151`)** | Pure-Rust `ring` HPKE + ECH (`pod-tls`, `pod-dns`, `pod-proxy`, `pod-ws` `features = ["ech"]`, zero new external crates) is wired into `podnet` (`--ech off\|auto\|strict\|CONFIG`, `--ech-grease`, `PODNET_ECH*`, `max_name_length` checks, `doctor` ECH status, `tests/ech.rs`). |
| H-15 | hard | hard | A failed health check ends only the first WARP session. Because the listener binds before the session is ready, queued clients receive `ECONNRESET`. |
| H-16 | very hard | measured | WARP registration returns HTTP 429 after about 10 calls in 90 minutes and clears after about 30 minutes. Idle MASQUE sessions close near 5 minutes (T-414 handed off in COORD-144 `#802`). |
| H-17 | hard | handed to relay (COORD-098) | The relay contract states no node-silence bound. A half-open TCP write fails at 938.5 s at default `tcp_retries2` and at 3.5 s when `tcp_retries2=2`. Tracked in T-406/T-478 (`#604`). |
| H-18 | hard | hard | No pair-renewal endpoint exists and pool hosts answer 503. Design: `POST /v1/pair/NAME/renew`, renew at 48 h, one shared pair store, and a systemd timer. |
| H-19 | hard | fixed (T-476) | Worst-case bytes before a reverse-relay move are `move_bytes + PAIR_WINDOW + 2 * CHUNK + 64`. `tests/transfer_relay.rs` moves at `160 KiB` (`<= 191 KiB`) under the 1 MiB cap; T-476 landed in `podcrates v0.86.0`. |
| H-20 | hard | hard | Two public transit relays answer on port 443 and `podnet` already dials them. No podnet-owned mailbox exists. |
| H-21 | very hard | very hard | A rootless two-NAT namespace lab reproduces cone and symmetric-like failures. The relay carries candidates inside a session, not before it. |
| H-22 | hard | hard | The concurrency semaphore exists. A 32-request window helps at high RTT (3.35 s down to 0.91 s at 200 ms), after fixing ID matching and backoff first. |
| H-23 | hard | shipped (`#495`) | `pod-wg` interoperates with Linux kernel WireGuard in both roles; WireGuard carrier (`wg:`) is wired in `podnet` (`v0.4.0-beta.21`). |
| H-24 | hard | shipped (`#500`) | RFC 6062 TURN TCP (`Allocate`, `Connect`, `ConnectionBind`) is wired in `pod-turn` (`v0.86.0`) and `podnet` (`turn:`). |
| H-25 | hard | partial (COORD-140) | Shadowsocks AEAD server (`link` `ss` service) shipped; Trojan accept parser in `pod-egress` is tracked in T-295 (`COORD-140 #785`). |
| H-26 | hard | hard | Release binaries build default features; `full` adds only pure-Rust crates (no C dependency risk). A build matrix and binary-size decision remain. |
| H-27 | very hard (as a set) | mostly shipped | Of `#484`–`#501`, `#486` (MASQUE `QUIC-1..5`), `#487`, `#489` (podnet side; COORD-145 `#803` for `pod-services`), `#490`–`#496`, and `#499`–`#501` are shipped; only `#497` (T-374) and `#498` (T-375) remain blocked on outside resources/owner. |
| H-28 | hard | hard | One unprivileged uid 1000 process can combine Landlock, hide-`/proc`, and seccomp holds. `bind-netns-vm-denied` does not produce the read-only memory state. |
| H-29 | hard | fixed (T-479) | Seven of eight named flaky tests exist; `quick_tunnel_standin_serves_a_visitor_over_http2` was stale and removed from `docs/HANDOFF.md`. `T-479` is done. |
| H-30 | hard | unchanged (deferred) | Bare `cargo install` skips prereleases. `cargo publish --dry-run` catches missing registry versions; `podcrates` publishes before `podnet` (crates.io publish deferred by owner). |
| H-31 | very hard | **solved for `#407` (T-210)**; `#149` waits on team token | Official `cloudflare-warp` `2026.8.2115.0` capture confirmed the closed `WarpAccount` enum (`free`, `limited`, `unlimited`, `team`) and `free` returning `warp_plus: true`. `warp_plus_label` (`src/warp/identity.rs`) now checks the closed paid set (`unlimited`, `team`, `premium`) plus `premium_data > 0`. Zero Trust `CF-Access-Jwt-Assertion` exists in `pod-warp` (`Api::with_team`); CLI wiring (`#149`) waits on `pod-warp::Account` fields and a live Zero Trust token. |
| H-32 | hard | mostly done | The size allowlist is empty (`0` allowlisted across 840+ Rust files); all shared crates except `pod-ts` (`T-123`/`T-124`) are taken at `podcrates v0.86.0`. |

## Changes landed directly from this study

1. **H-02**: `crates/podnet-netns/src/seccomp/mod.rs` and `crates/podnet-netns/src/seccomp/accept.rs` refuse `listen(2)` on `Sock::Kernel` with `EPERM`, verified by 3 cases (bare IPv4, bound IPv4, bare IPv6) plus `/proc/<pid>/fd` inode checks in `tests/pod_seccomp/kernel_listen.rs`.
2. **H-04**: `crates/podnet-netns/src/netns/udpflow.rs` reassembles IPv4 UDP fragments up to 65,507-byte payloads (`NETNS_UDP_LIMIT = 65_507`), verified by 17 unit tests (including oldest-set eviction) and `tests/pod_seccomp/netns_udp.rs`.
3. **H-05**: `crates/podnet-vnet/src/{addr,shim}.rs`, `crates/podnet-vnet/shim/podnet-vnet.c`, and `src/cli/cmd/net/shim.rs` generate per-run `PODNET_VNET_PREFIX` values, cap prefixes at 59 bytes, reject invalid or non-UTF-8 prefixes before build with exit 64, copy full 107-byte `sun_path` names, and print ignored-prefix warnings unconditionally to stderr.
4. **H-09**: `docs/reports/netbird-netstack-2026-11-27.md`, `docs/networks.md`, and `crates/podnet-netns/src/upstream.rs` (T-247: `netbird:[PORT]` expands to `127.0.0.1:PORT`).
5. **H-10**: `docs/warp.md` corrects the TCP probe description to reflect live TCP carriage over MASQUE.
6. **H-11 & H-19**: `scripts/live-throughput.sh` captures non-2xx HTTP status, `cf-ray`, and error bodies instead of discarding them with `curl -f`; `tests/transfer_relay.rs` sets the 1 MiB cap test move threshold to 160 KiB (`<= 191 KiB`); COORD-144 (`#802`) hands off `pod-warp` idle reset and `pod-cloudflare` `ha_connections`.
7. **H-13 (`#140` / T-002)**: `scripts/capture-rig/` (hermetic, idempotent, four-layer client capture rig), `docs/reports/warp-client-capture-2026-11-27.md`, `src/warp/l4.rs` (Stream 0 `cf-connect-ip` bootstrap + DoH-over-L4 IP-literal `CONNECT`), and `scripts/live-batch2.sh` (`--l4` upgraded to a live `warp=on` + 20 MB HTTP 200 check).
8. **H-14 (`#151` / T-004)**: `src/ech.rs`, `tests/ech.rs`, `--ech`/`--ech-grease`, and `pod-tls`/`pod-dns`/`pod-proxy`/`pod-ws` `features = ["ech"]` (pure-Rust `ring` HPKE, zero new external crates).
9. **H-31 (`#407` / T-210)**: `src/warp/identity.rs` (`warp_plus_label` closed paid account set backed by official `cloudflare-warp 2026.8.2115.0` `WarpAccount` enum).
