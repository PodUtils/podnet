A prerelease of `podnet`, for tests. It follows v0.4.0-beta.8.

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text. `pod-report.schema.json` is the JSON
Schema of `podnet pod --report`. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.9` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.9 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.9   # rebuild and compare (x86_64, aarch64)
```

`podnet update` does the first three checks itself.

## Breaking

* A carrier address of `podnet link` takes a query (`ADDRESS?carrier=tcp`).
  The first `?` starts the query, so a unix path with `?` in it cannot be
  used. A repeated key, an unknown key or a secret key (`password`, `key`,
  `token`, `identity`) exits 64 (T-306).
* `podnet link listen|connect --name NAME --detach` with a name that a live
  link holds exits 64. Before, it gave back the same instance (T-308).

## Changes for a tester

* `podnet link`:
  * The TCP carrier with TLS 1.3 (build feature `tcp`): each end pins the
    Ed25519 key of the other end in the handshake; a key that is not pinned
    exits 77 (T-268).
  * Names for live links (`--name`); a name keeps the key of its peer, and a
    changed key exits 77 (T-308). The query keys of a carrier address
    (T-306). `podnet components [--json]`: each carrier and service of the
    build (T-310).
  * Services at a peer: `raw` (half-close both ways, T-293) and `socks5`
    (CONNECT; T-291).
  * The mesh: `--announce` sends a signed route announcement on each link
    (T-285); each hop signs its part of the path (T-287); the route table
    (T-286); `link dial --announce --node FINGERPRINT` reaches a node through
    other nodes (T-287); the control verb `routes`.
  * `podnet link mesh --control unix:PATH [--json | --metrics]`: the local
    view of the nodes and the edges of a mesh, with limits (T-289).
  * Link groups: `peer:FINGERPRINT/SERVICE` networks as members of a router
    group, with limits and probes (T-288).
* Networks: `devtunnel://TUNNEL`, a Dev Tunnels network for TCP streams; the
  token comes from `PODNET_DEVTUNNEL_TOKEN_FILE` or `PODNET_DEVTUNNEL_TOKEN`
  (T-320). `podnet net doctor --network SPEC` brings up one network and names
  the stage that failed (T-320, T-321).
* `podnet route --control`: `--add-door`, `--remove-door`, `--add-network`
  and `--remove-network` with no restart; counters for each door in
  `--status` and `--metrics` (T-327).
* `podnet exit --stdio`: a SOCKS5 exit on stdin and stdout, with no
  listener. CONNECT uses the stream; UDP goes in frames on the same stream
  (`docs/proxies.md`, "Exit on stdio") (T-329).
* `podnet pod --report FILE`: a JSON report of the backend, the hold, the UDP
  limit and the exit code; its schema is a file of the release (T-330).
* `docs/router.md` says that a group balances flows, not the bytes of one
  flow.
* The shared crates of PodUtils/podcrates are at `v0.36.0` (T-137).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`. The test guide is GitHub #89.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* No crates.io release of `podnet` exists.
* The Rekor inclusion proof is not checked by `podnet update`.
* `rsa` 0.10.0-rc.18 (pinned by russh) has the advisory RUSTSEC-2023-0071, a timing
  leak of an RSA private key. podnet makes Ed25519 keys. Give podnet no RSA key (T-326).
* `podnet link` has the unix, memory and TCP carriers. The WebSocket,
  HTTP/2, long-poll, SSE, QUIC and UDP carriers come with `pod-link` of
  podcrates. A middle node of the mesh sees the bytes of a stream: the keys
  from end to end wait for `pod-e2e` (T-298).
* The `socks5` service at a peer has CONNECT only (no BIND, no UDP
  ASSOCIATE).
* Not measured against a live service: a Dev Tunnels account.
* Not measured against a live service: a TURN server, Serveo,
  localhost.run, Pinggy and Sandhole.
* The limits of v0.4.0-beta.8 stand.
