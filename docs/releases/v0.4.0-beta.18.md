A prerelease of `podnet`, for tests. It follows v0.4.0-beta.17. It has the fixes of the black-box QA pass of 2026-11-23 (GitHub #687, #689 to #706), the shared verifier of `pod-release` in `podnet update`, and the shared crates of PodUtils/podcrates at `v0.82.0`.

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text. `pod-report.schema.json` is the JSON
Schema of `podnet pod --report`. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.18` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.18 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.18   # rebuild and compare (x86_64, aarch64)
```

`podnet update` checks SHA256SUMS and the cosign bundle itself, with the entry of Rekor and its timestamps.

## Breaking

`podnet update` (T-494):

* A cosign bundle with no entry of Rekor is refused. A bundle whose signed entry timestamp, inclusion proof,
  checkpoint or RFC 3161 timestamp does not verify is refused.
* `--version` takes only `v` and a semver version with no build part. `0.3.0`, `v1`, `v1.2` and `v1.0.0+b` exit 64.
  Before, some of them reached the network and exited 69.
* With no `--version`, a binary that is newer than the newest release prints "podnet vX is newer than the newest
  release vY; nothing to do" and exits 0.
* The new binary gets the mode of the old binary, with no write for the group or others and no set-user-ID bit.
  Before, the mode was always 0755.
* When podnet cannot write `podnet.prev`, the update continues with a warning. Before, the update failed.
* Some error lines changed. A rollback with no kept binary says "there is no .../podnet.prev: no update kept a
  binary before this one".

`podnet tunnel` (T-513):

* The edge can refuse a start with "retry: yes", or not know a new quick tunnel yet ("Tunnel not found"). podnet
  then starts one more time. When that start fails too, podnet exits 75. Before, it exited 69. The first line starts
  with "the quick tunnel did not register" or "the named tunnel did not register".

The listeners (T-515, T-523):

* `connect -L` and `tunnel --e2e --listen` exit 69 when the bind fails. Before, they exited 1.
* A unix listener in a directory that does not exist exits 69 (`connect`, `net proxy`, `net switch`, `serve --local`,
  `git serve --local`, `warp proxy`, the control socket of `link`). Before, it exited 1.
* `warp proxy` and `warp forward` bind before they register a device. A refused bind gives one line with a next step.

`podnet pod` (T-516, T-517, T-527, T-531):

* SIGTERM, SIGINT or SIGHUP from a process: podnet sends the signal to the program, prints "podnet pod: SIGNAL:
  stopping the program" and exits with the status of the program (128+N when the signal ended it). After 10 s, or at
  a second signal, each process of the pod gets SIGKILL. Before, podnet stopped and the program continued to run.
* A program that cannot run (a missing path, a file with no execute bit, a name that is not in PATH) exits 3 with one
  line on each backend. Before, the seccomp backend exited 127 with no line.
* A bad `PODNET_RESOLVE` exits 78. Before, podnet ignored it and exited 0.
* The SOCKS5 reply codes of the front door (`pod --serve`, `net proxy`, `net tailscale`) follow RFC 1928 by the
  cause: a refused connection gives 0x05, an unreachable host or a name with no address gives 0x04, an unreachable
  network gives 0x03. The code of an upstream that refused passes through. Before, most failures gave 0x01.

`podnet rules check` (T-518, T-519):

* A policy file that is missing, that podnet cannot read, or that podnet cannot parse exits 78. Before, it exited 1.

The JSON documents (T-519):

* `rules check --json`, `init check --json` and `ci check --json`: `schema` is the integer 1. The string id is in the
  new key `kind`.
* `warp status --json`, `init enroll --json`, `offline spool --json` and `warp probe --json` get the keys `schema`
  and `podnet`. `pod doctor --json` gets the key `podnet`; its schema id does not change.

`podnet net` (T-509, T-525):

* `net shim`, `net socksify`, `net ts-shims` and `net passwd-shim` with an `--out` on a noexec file system exit 78.
  Before, they exited 0 and gave a shim that cannot load.
* `net shim` makes a new `PODNET_VNET_PREFIX` for each run. Before, each run used `podnet-vnet`. A prefix that is not
  valid exits 64 before the build. The notes of `net shim` go to stderr; stdout has only the exports.

`podnet autostart` (T-532):

* `autostart remove` with an unknown name exits 69. Before, it exited 1.

The text (no exit code changes):

* Error lines name each cause one time and give the hint of the true hop (T-521, T-522).
* `net doctor` says "not needed" only when a TCP connect on the loopback works (T-524).
* The warning about the state directory names the directory and the directory that podnet uses, one time (T-529).
* The timeout line of `send` gives the time of `--timeout` (T-520).

## Changes for a tester

* `podnet update` uses the verifier and the update of the shared crate `pod-release`. It checks the entry of Rekor
  and the timestamps of the bundle. The flags `--check`, `--version`, `--force` and `--rollback` stay (T-494).
* The shared crates of PodUtils/podcrates are at `v0.82.0` (T-483 to T-506). The copies of shared code take the
  crates: the HTTP head readers and the CONNECT client of `pod-proxy`, the request parser of `pod_core::http1`, the
  file writes of `pod_core::files`, the groups of the help in the model of `pod-manual` (T-473). The control socket of
  `route` answers a bad head with 400, 431 or 505 (`docs/router.md`).
* New capabilities (the deferred features, `4df28952`): the link carriers `serial:` and `hf:` (T-376), and `ntp`,
  `smtp` and `imap` behind their Cargo features (T-365); a TURN fallback of `link p2p` (T-366); `cover` (T-369); record shaping and `doctor --shape` (T-370);
  deferred responses and a traffic generator (T-371); the end-to-end session (T-373); `offline` (`spool`, `discover`,
  `bundle`, `capture`, `pair`, `replica`) (T-376); `host probe`, `host stat`, the egress policy, `init`, `forge
  clone`, `ci check` and the status page (T-377); `harness` (T-378). The packet sidecar is behind the Cargo feature
  `sidecar`; the release binaries do not have it (T-372).
* `pod --backend seccomp`: `listen` on a kernel socket fails with EPERM (T-507). `pod --backend netns`: a UDP datagram
  of up to 65,507 bytes in IPv4 fragments arrives whole (T-508).
* `pod --backend netns`: names resolve when `/etc/resolv.conf` is a mount of a deleted file, and at each loopback
  nameserver of the host (T-499, T-503). A refused network namespace gives one line (T-482). A failed connect of the
  program gives a line at the default level (T-496). The seccomp backend counts one refused flow one time (T-532).
* `warp`: the front doors work when a proxy of the environment is set and the host has no default route (`1325d5bb`).
* Error lines and the rows of `--check` name each cause one time, with no Debug text, and give the hint of the true
  hop: a dead proxy, a name that does not resolve, a refused port, a page of a gateway in place of the API of the
  quick-tunnel service (T-497, T-498, T-502, T-521, T-522). `bench` text shows `-`, not `null`, for a run with no
  answer (T-530).
* `podnet man exit-status` and `docs/cli.md`: `doctor` and `bench` exit 1 when no leg or no request works; 69 is for
  the commands that start a session (T-528).
* `podnet pod --help --json` prints JSON, and the manual of `pod` has its flags (T-500). Each `podnet` command of the
  documents parses (T-526). The version line is a contract (T-484).
* The image `ghcr.io/podutils/podnet` has an attestation of the provenance of its manifest list. The release checks
  that each image holds the binary of the release (T-487).
* Dependabot updates: the minor and patch group with `noq-proto` and `noq-udp` 1.5.0 (#684), `taiki-e/install-action`
  2.90.5 (#682), trufflehog 3.99.9 (#681), the build image `library/rust` 1-alpine (#680).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`. The test guide is GitHub #89.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* Two entries of the QA pass are partial; the rest waits for a tag of PodUtils/podcrates (COORD-115,
  PodUtils/podnet#707; `docs/decisions.md`, 2026-11-23):
  * A file that the kernel cannot run (`ENOEXEC`, a binary of another architecture) still exits 127 with no line on
    the seccomp backend (T-516).
  * The line for a name that no resolver answers can be long, for example 631 bytes from `bench` (T-522).
* No crates.io release of `podnet` exists.
* Experimental (no scenario of the release binary): `podnet net tailscale`, `podnet ssh-relay` and `podnet warp license`.
  Only the tests with stand-ins check them.
* The release binaries have the link carriers `unix`, `memory`, `serial` and `hf` only (`docs/link.md`, T-428, GitHub
  #620).
* The limits of v0.4.0-beta.13 stand.

## Known problems

* About one `live` run of six fails at the public relay: the relay keeps a lost socket of a node after a reset (T-406,
  PodUtils/podnet#604). At times, the door of WARP shows a certificate of Let's Encrypt to `warp scan` (T-406, live
  45162920304).
* A quick tunnel gets HTTP 530 from the edge for some requests, at times (T-488).
* Two parallel SSH sessions through one relay node: one can hang (T-478).
