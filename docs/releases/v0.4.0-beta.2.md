A prerelease of `podnet`, for tests. It follows v0.4.0-beta.1.

A user of `cfrs` reads the notes of v0.4.0-beta.1 first. They give the
rename and the move from `cfrs`.

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.2` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.2 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.2   # rebuild and compare (x86_64, aarch64)
```

`podnet update` does the first three checks itself.

## Breaking

A command or a script written for v0.4.0-beta.1 must change for each item
below.

1. Each message of `podnet pod` and `podnet pod doctor` starts with
   `podnet pod:` (was `podnet-netns:`). `podnet pod --version` prints the
   line of `podnet --version` (T-135). Change each script that matches the
   old prefix.
2. The seccomp backend has a new default ceiling of tracked sockets:
   `(RLIMIT_NOFILE - 64) / 2`, from 64 to 65536 (was 4096). The supervisor
   raises its soft limit to the hard limit after it starts the program. The
   program keeps its limit. Use `--flow-budget N` (64 to 1048576) to set the
   old value. A value above the default gives a warning (T-181).
3. A `socket` call that fails because the supervisor has no descriptor for a
   socket pair gets `EMFILE` (was `EIO`) (T-181).
4. At the exit of a seccomp pod, one line on stderr gives the counts of the
   refused `socket` calls, when a call was refused (T-181).
5. The seccomp backend gives the program the accepted inbound connection
   itself, with no relay and no socket pair. The accepted socket has the name
   of the listening socket, and the supervisor reads no byte of it (T-150).
   With `--flow-log`, the pod relays each TCP flow again, to count bytes
   (T-157).
6. The netns backend: `podnet pod` returns the exit code of the first program
   at once. The pod and its router stay until each process of the namespace
   ends. A script that waited for the end of the router must wait for the
   processes (T-108).
7. `podnet warp nc` refuses a destination name over 255 bytes with
   `invalid destination: ... is longer than the 255 bytes of SOCKS5`. Before,
   it cut the name. The error words of the SOCKS5 datagram path are those of
   `pod-proxy`. A reply with a SOCKS version other than 5 is refused
   (T-224).
8. A seccomp pod answers a connect or a datagram that a `reject` or `block`
   rule refuses with `ECONNREFUSED` (connect) or `EACCES` (datagram). A
   `-r` rule with an unknown action is a usage error, exit 64 (T-156).

The keys of `podnet doctor --json` do not change. `podnet pod doctor --json`
has the new key `flow_budget` (T-181) and a new row for netfilter (T-152).

## Changes for a tester

Pod backends (`podnet pod`, `warp exec`, `warp shell`):

* `-r` takes the actions `reject` and `block`, for TCP and for datagrams
  (T-156).
* `--default-action allow|reject` and `--flow-log FILE` (T-157). The log has
  one JSON line for each decision and one at the close of each relayed TCP
  flow, with `bytes_out` and `bytes_in`.
* `--learn FILE` records the destinations. `--fail-on-violation FILE` refuses
  a destination that is not in FILE, and exits 4 when the program exits 0
  (T-158). Both are a usage error with `--serve`.
* `--flow-budget N` and the row `flow budget (seccomp)` of `pod doctor`
  (T-181).
* `pod doctor` has the row `netfilter in a namespace (not a backend)`. No
  backend uses it (T-152).
* The seccomp relay has a buffer of 64 KiB for each direction (T-151).
* The seccomp backend gives the accepted inbound connection to the program
  (T-150).
* The netns backend: generic UDP, with a flow table (60 s idle, 256 flows)
  (T-111). The pod lives past its first program (T-108). A large TCP
  download keeps full speed with a bounded buffer (T-226).
* `podnet-netns` uses `pod_proxy::udp` for the SOCKS5 datagram path (T-224).
* Fuzz targets for the seccomp handlers: `seccomp_sendto`, `seccomp_sendmsg`,
  `seccomp_sockopt` (T-154).

WARP:

* The send poller of the WARP QUIC socket keeps its wake-up (T-225).

Tunnel and services:

* `podnet connect URL --stdio` carries one stream on stdin and stdout, for an
  SSH `ProxyCommand` through `tunnel --forward` (T-082).
* `serve --tar`: `GET /PATH/?tar` gives a directory as one tar stream
  (T-085).

Git:

* An SSH server for `git-upload-pack` and `git-receive-pack`, with host key,
  `authorized_keys` (ed25519 and ecdsa) and `anon_read` (T-093). It is a
  library item; no command starts it yet.

Virtual network:

* `net socksify --cidr` (repeatable), `PODNET_SOCKS_CIDRS` and
  `net shim --socks-route` send chosen destinations to the SOCKS5 door
  (T-167).
* `net passwd-shim` and the row `passwd entry for this uid` of `net doctor`
  (T-168).
* A reader of a wg-quick file, with optional reserved bytes (T-116). It is a
  library item.

The CLI and doctor:

* `podnet pod --version` prints the line of `podnet --version` (T-135).

Build and crates:

* The code moved into the crates `podnet-core`, `podnet-serve` and
  `podnet-vnet`, and into smaller files. The library paths stay the same
  through re-exports (T-046, T-047, T-048, T-051, T-033, T-034, T-037,
  T-038, T-040, T-041, T-042, T-044).
* podnet takes the shared crates of `PodUtils/podcrates` up to v0.13.0,
  with `pod-ws` (T-137).
* CI checks the citations of the last commit (T-015). The live step updates
  from v0.4.0-beta.1 (T-024). The publish to crates.io is a switch (T-023).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* No crates.io release of `podnet` exists.
* The Rekor inclusion proof is not checked by `podnet update`.
* T-152: the netfilter probe is not measured on a container, and not on a
  runner with AppArmor limits on user namespaces. No backend uses it.
* T-181: the counters are for each pod. The per-door counters wait for the
  router. The run of 5000 connections is not measured.
* T-093: `podnet git serve` does not exist yet (T-094).
* T-151: the netns TCP path was slow for a large transfer before T-226; the
  speed on a real proxy is not measured.
* T-167: the external shim of the issue is not measured. T-168: `ssh-keygen`
  on a host with no passwd entry is not measured.
* T-154: the libFuzzer run is not made for this release.
* T-111: a full queue of a UDP flow holds the datagram, with no failover.
* T-116: a wg-quick file with `PresharedKey` is read, but the WireGuard code
  does not use it yet.
