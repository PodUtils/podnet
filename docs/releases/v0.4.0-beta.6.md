A prerelease of `podnet`, for tests. It follows v0.4.0-beta.5.

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.6` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.6 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.6   # rebuild and compare (x86_64, aarch64)
```

`podnet update` does the first three checks itself.

## Breaking

* The README is short. The detail is in the topic documents of `docs/`
  (`docs/install.md`, `docs/tunnels.md`, `docs/router.md` and others). A
  link to a section of the old README does not resolve (T-259).
* `podnet net doctor`: a `tailscaled` that is not logged in (state other
  than `Running`) is now `fail`. Before, it was `ok` (T-115).
* `pod --serve`, `net proxy` and `net tailscale` run on one front door
  (T-061):
  * Each door takes at most 1024 live clients.
  * `pod --serve` answers a SOCKS5 BIND with "command not supported"
    (0x07). Before, it treated BIND as CONNECT.
  * A 502 or 403 answer of `pod --serve` has a body with the text of the
    failure. The text can name the upstream address.
* `podnet ssh-relay` reads the relay from `pod-services`: with no flag it
  uses `pinggy`. `--service NAME` selects a known relay. `--server` with
  no `--service` needs `--user` and a URL rule (exit 64) (T-166).
* The binary has the IPv4 fragmentation of `pod-netstack` on: each
  userspace stack holds a buffer of 64 KiB for fragments (T-248).

## Changes for a tester

* `podnet route`, the control socket (T-180): `--control unix:/PATH`
  with `--select GROUP=MEMBER|auto`, `--rotate MEMBER`, `--reconnect
  MEMBER` and `--interval SECONDS`. A rotate brings the new link up before
  it closes the old one. The router file takes `state_dir`.
* `podnet route` (T-097, T-098): `--status --metrics` prints the metrics
  rows (also `GET /route/metrics`); the key `health.egress` checks the
  address a member leaves by; a door carries UDP ASSOCIATE; the key
  `resolvers` makes a member resolve names through its own network.
* `podnet route`, guest wires (T-248): the key `guests` connects a guest on
  a unix socket (`unix:/PATH`, SOCK_SEQPACKET) or a TUN device
  (`tun:NAME`). The router ends the guest TCP at the SYN, dials through
  the rules, and refuses the guest's connect at once when the dial fails.
  Guest UDP has a bounded queue and counters.
* Networks: `wg:FILE` is a network of the registry (T-117): a WireGuard
  peer on a userspace stack, for `forward --network` and the router.
  `tailscale:SOCK` is a network of the router and of a group, and `route
  --check` and `net doctor` show the login state (T-115).
* `pod --serve --early-reply` (T-237, off by default): the door answers
  the client before the upstream connect. A failed dial then shows as a
  closed connection (`docs/proxies.md`, Early reply).
* `podnet doctor --json` (T-260): the lanes `masque_udp443` and
  `ws_upgrade` have a probe. The keys do not change.
* `podnet pod --backend netns` (T-249): the router of the pod runs on
  `pod-netstack`, with no cap on the destination ports. The hold of each
  SYN is `pod_hold::syn_hold` of podcrates.
* The help, the manual and the README describe each capability of podnet
  (T-259).
* podnet takes the crates of `PodUtils/podcrates` at v0.29.0 (T-137).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`. The test guide is GitHub #89.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* No crates.io release of `podnet` exists.
* The Rekor inclusion proof is not checked by `podnet update`.
* Not measured against a live service: the lanes `masque_udp443` and
  `ws_upgrade`, a real `tailscaled`, a WireGuard peer of another code base,
  a guest wire with a Linux guest kernel, the rotate of a WARP device.
* The limits of v0.4.0-beta.5 stand.
