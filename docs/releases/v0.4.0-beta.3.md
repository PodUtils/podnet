A prerelease of `podnet`, for tests. It follows v0.4.0-beta.2.

A user of `cfrs` reads the notes of v0.4.0-beta.1 first. They give the
rename and the move from `cfrs`.

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.3` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.3 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.3   # rebuild and compare (x86_64, aarch64)
```

`podnet update` does the first three checks itself.

## Breaking

A command or a script written for v0.4.0-beta.2 must change for each item
below.

1. `warp exec` and `warp shell` try the netns backend first, then seccomp
   (was seccomp first). The line of the backend ends with `Choice: REASON`.
   Give `--backend seccomp` for the old choice (T-113).
2. The netns backend refuses a TCP connect to the gateway `10.66.255.254` at
   once (a RST), and drops a datagram to it (not port 53). Before, the flow
   went to the proxy. `podnet pod --host-gateway` sends them to the loopback
   of the host (T-112).
3. A pod with the seccomp backend stops at its start with exit status 3 when
   the pod cannot read the memory of a program (`/proc/<pid>/mem`). Before,
   the program ran and each `connect` was refused (T-231).
4. A dual-stack socket that connects to the IPv4-mapped form of a fake
   address (`::ffff:198.18.x.y`, as .NET and Java do) goes to the proxy with
   the name. Before, the proxy got the fake address and the dial failed
   (T-233).
5. The netns router does not take a packet with an IP header under 20 bytes,
   or a fragment past the first, as a SYN (T-234).

`podnet pod doctor --json` has the new object `hold` and the new row
`read program memory` (T-230, T-231). The other keys do not change.

## Changes for a tester

The way out:

* `--egress SPEC` on each command: `direct` (as `--no-proxy`), a proxy URL (as
  `--proxy`), `relay` or `relay:URL` (as `--transport relay` and `--relay`).
  With `podnet pod`, each `--egress` is one `-x` hop of the chain, in its
  order. The old flags stay (T-060).
* `podnet pod -x` takes `socks5h+unix:/PATH` and `http+unix:/PATH` (T-060).

The file server and git:

* `podnet serve DIR`: `--list` (a listing in HTML and JSON), `--users FILE`
  with the roles read and write, `--pin`, `--anon-read`, `--hash-password`,
  `--upload` (PUT and a form, `--max-upload`), more than one `--local`, and
  `--ingress tunnel|relay|none` (the road to the visitors) with `--pair`
  (T-088 to T-091).
* `podnet share --local` and a directory in `share` (T-091).
* `podnet git serve --root DIR`: smart HTTP through a quick tunnel, SSH with
  `--authorized-keys`, `--ingress relay` through a relay pair, `git init`
  and `git urls` (T-092 to T-094).

Pod backends (`podnet pod`, `warp exec`, `warp shell`):

* `warp exec --detach --name N` keeps a pod under the supervisor: `podnet
  ps`, `logs`, `stop` (T-109). `warp exec --join N -- CMD` runs a command in
  that pod (T-110). `podnet pod --session DIR` shares the inbound listeners
  and the fake DNS table.
* `podnet pod --host-gateway` (T-112).
* `pod doctor` prints `hold netns` and `hold seccomp`: the level
  (`enforced`, `advisory` or `none`) and what the backend does not hold
  (T-230).
* `scripts/pod-runner-measure.sh` measures the pod with the runner of
  `actions/runner` v2.338.2, a Node `fetch`, `actions/checkout` and
  `actions/setup-node` (`docs/reports/pod-runner.md`, T-229).

WARP:

* Each sender that waits on the WARP QUIC socket gets its wake-up (T-228).
* podnet uses noq through `pod-quic` (no quinn in the tree) (T-137).

Library and crates:

* `podnet-core` has the network types (`Target`, `Dial`, `Datagrams`,
  `Network`, `Link`; T-055), the dialers (T-056), the combinators `Chain`,
  `Rules`, `Race` and `Failover` (T-058). `podnet::networks` is the registry
  of the networks and the parser of their specs (T-059).
* podnet takes `pod-quic` and `pod-hold` of `PodUtils/podcrates` v0.15.0: the
  generic core of the hold of the pod backends is in `pod-hold` (T-137,
  T-232).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* No crates.io release of `podnet` exists.
* The Rekor inclusion proof is not checked by `podnet update`.
* T-060: a chain of `--egress` works with `podnet pod` only. The registry has
  no WARP network yet (T-057).
* T-229: `run.sh` of the runner is not measured to its long poll.
* T-231: the rules of `podnet pod` do not apply to loopback TCP under the
  seccomp backend yet.
