The first prerelease of `podnet`, for tests. `podnet` is the new name of
`cfrs`. The Cloudflare tunnel is one adapter of podnet. The version line
continues above v0.3.0-beta.12.

The releases up to v0.3.0-beta.12 are the releases of `cfrs`. They have
`cfrs-TARGET` and `pod-netns-TARGET` assets. They are signed as
`https://github.com/Azathothas/cfrs/.github/workflows/release.yml@refs/tags/TAG`.
Use that identity to check them. Releases from v0.4.0-beta.1 have the
assets and the identity that this note gives.

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.1` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.1 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.1   # rebuild and compare (x86_64, aarch64)
```

`podnet update` does the first three checks itself.

## Move from cfrs

1. Run `cfrs autostart remove NAME` for each entry, and `cfrs warp down`.
   podnet does not see the markers and the units of cfrs.
2. Install podnet new. `cfrs update` cannot install it: it looks for the
   assets of `cfrs`.
3. To keep the WARP device, move `~/.local/state/cfrs` to
   `~/.local/state/podnet`, or set `PODNET_STATE_DIR`. podnet registers no
   new device then.
4. Rename each variable, unit, path and metric of the list below in your
   scripts, units and dashboards.

## Breaking

A command or a script written for v0.3.0-beta.12 must change for each item
below. Item 1 to 12 are the rename.

1. The binary is `podnet` (was `cfrs`). The assets are `podnet-TARGET`
   (were `cfrs-TARGET`). The manual page is `podnet.1` (was `cfrs.1`). The
   repository is `PodUtils/podnet`, and the signature identity is
   `https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/TAG`.
2. The `pod-netns` binary and its assets are gone. Use `podnet pod`. It has
   each option of the old command line, and `podnet pod doctor`. The crate
   `podnet-netns` (was `pod-netns`) is a library only.
3. The image is `ghcr.io/podutils/podnet` (was `ghcr.io/azathothas/cfrs`).
4. The variables change: `CFRS_X` is `PODNET_X`, `CFRSNET_X` is
   `PODNET_VNET_X`, and `CFRSSOCKS_X` is `PODNET_SOCKS_X`. The old names have
   no effect. The variables `POD_NETNS_QUIET` and `POD_NETNS_TEST_MEM` of the
   pod library are `PODNET_NETNS_QUIET` and `PODNET_NETNS_TEST_MEM`.
5. The state directory is `~/.local/state/podnet` (was
   `~/.local/state/cfrs`). The run directory is `$XDG_RUNTIME_DIR/podnet`
   (was `$XDG_RUNTIME_DIR/cfrs`), and `podnet-UID` in the temporary directory
   (was `cfrs-UID`). podnet does not read the old directories.
6. The default name of the TUN interface is `podnet0` (was `cfrs0`).
7. The units are `podnet-NAME.service` (were `cfrs-NAME.service`). The cron
   marker is `# podnet autostart NAME`. The blocks and files of `warp up`
   have the names `podnet`: the block `# >>> podnet warp up >>>`,
   `90-podnet-warp.conf` and `conf.d/podnet-warp.fish`. `podnet warp down`
   does not remove the files of cfrs.
8. The metrics are `podnet_*` (were `cfrs_*`).
9. The paths of the edge are `/__podnet/ws` and `/__podnet/unlock` (were
   `/__cfrs/ws` and `/__cfrs/unlock`). A client and a server must both be
   podnet.
10. The User-Agent is `podnet/VERSION` (was `cfrs/VERSION`). The realm of the
    proxy login is `podnet`.
11. The log filter is `podnet=LEVEL` (was `cfrs=LEVEL`), for example
    `RUST_LOG=podnet=debug`.
12. The default directories of the file commands are `~/Downloads/podnet`
    and `~/podnet-uploads`.

Output and exit codes:

13. `podnet pod doctor` uses the verdict words of `podnet doctor`. The text
    form gives `ok` or `fail` for each probe and each backend (before: `ok`,
    `no`, `available`, `unavailable`). The JSON form has the new keys
    `schema` (1), `verdict` for each capability, and `verdicts` (`netns`,
    `seccomp`, `any`). The keys `ok`, `backend_netns`, `backend_seccomp` and
    `backend_available` stay. The exit code stays 3 when no backend can run.
14. A refused TCP bind exits 69 in `net switch`, `net proxy`, `warp proxy`,
    `relay connect --listen` and `net tailscale`.
15. `tunnel --config` with an origin flag (`--port`, `--forward`,
    `--no-tls-verify`) exits 64 and names the flag. It ignored the flag
    before.
16. `relay stop` checks the pair before it stops the local node.
17. The ready line of `share --json` has the keys `schema` and `podnet`.
18. `doctor --agent`: a row is `ok` only when the index host and the file host
    both answer. `doctor --relay URL` checks the relay that you name.

Behaviour:

19. An ingress `path:` rule matches the decoded path, as cloudflared does:
    `%XX` is decoded, `+` stays. A rule for `/a b` now matches `/a%20b`.
20. The library static path decodes `+` as a plus. A bad escape (`%zz`) is
    refused.
21. The pair file of the relay always has mode 0600. `load` checks the file.
22. `warp export` writes the reserved bytes in the file. `warp export
    --check` checks a file.

## Changes for a tester

Seccomp backend (`podnet pod`, `warp exec`, `warp shell`):

* A TCP socket stays tracked after its `connect`. Its options and addresses
  come from its entry. There is one entry for each socket of each process,
  and copies of a descriptor are tracked.
* A plain upstream descriptor goes to the program after its handshake.
* ICMP datagram sockets, `recvmmsg` and UDP names over 255 bytes work.
* A slow `connect` dial does not stop the supervisor for other calls.
* The close of a UDP socket stops its relay and frees its descriptors. A
  datagram written with `write(2)` leaves the pod. `bind` on a datagram
  socket is recorded, and `getsockname` reports it.
* `connect(AF_UNSPEC)` dissolves the association of a datagram socket. A
  connected datagram socket takes datagrams from its peer only. Datagram and
  ICMP sockets keep their IP-level options.
* The limits of the UDP relay (ICMP errors, path MTU) are in the
  documents.
* The fake DNS pool refuses at its end, and names match with no case.
* A differential check compares the socket calls with the host kernel. It
  closed six TCP gaps.

WARP:

* A probe of the TCP data path renews a session that carries no TCP.
  `warp tun` has a SYN probe and `--session-max-age`, and sets `rp_filter`
  to 0 on its interface.
* `warp exec`, `warp shell` and `warp nc` find a running `warp up` that has
  another state directory. `warp exec` and `warp shell` take `--backend`,
  and name the backend in one line.
* `warp forward` has the pins of `--resolve` and a list of the forwards.
* `status`, the ready document and `warp status` have `data_path` and the
  time of the last TCP probe. `warp status` names the `warp-tun` instance.
* `warp up --tun` forwards `--replace` and refuses the flags that it cannot
  forward. `warp down` and `warp up --persist` own the fish file only when
  podnet wrote it.
* `warp ssh-config` prints a `ProxyCommand` with the same quote as `--write`.
* `warp proxy --dns` has a bound and a counter.

Tunnel and DNS:

* `tunnel verify` keeps the tunnel up when this host cannot resolve the name
  yet, pins the new public name while the process runs, and names the remedy
  when the name does not resolve. Quick-tunnel provisioning does not retry a
  DNS failure that cannot recover.
* The DoH resolver keeps one connection for each server.
* `WebSocketTunnel` dials through the egress layer and parses IPv6.
* An `http://` proxy URL with no port has one default port in podnet and
  podssh.
* The errors of an ingress or config file name the line. The tailnet front
  door warns when `tailscaled` is not logged in.

Virtual network and relay:

* The switch counts each packet that it drops. A stack over a switch link has
  bounded queues.
* The listener table of `net doctor` names each command that listens.
* `net proxy --forward` takes a name as a real target, reports the failed hop
  and reports a failed bind before it prints the forward. `net proxy --map`
  fills the gateway resolver and the shim table.
* The doors of `net proxy`, `net tailscale` and `pod --serve` have a deadline
  for the client handshake. A unix listener claims its socket path first. The
  datagram socket of the vnet shim takes the same user only.
* A relay `close` aborts the session task of the node. The relay node waits
  after a local end of stream. `relay connect --listen` has the instance
  surface of `connect -L`.

Other commands:

* `serve` of a directory with no `index.html` logs no WARN for the 404 at `/`.
* A nested detached start does not inherit `PODNET_DETACH_SUPERVISED`.
* `agent status --json` prints the status as JSON.
* `--no-verify` is in the README with its limits.
* The start of a session no longer changes the global git identity (a
  development fix).

Checks:

* A CI job runs the tests with the loopback down.
* The source tree moved: `src/main.rs` is split into the module `src/cli/`.
  The behaviour is the same (a parity snapshot checks it).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet bug-report`.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* No crates.io release of `podnet` exists.
* The Rekor inclusion proof is not checked by `podnet update`.
