A prerelease of `podnet`, for tests. It follows v0.4.0-beta.19. Its release binaries have the network link carriers (the feature `release`: `tcp`, `ws`, `h2`, `quic`, `udp`, `poll` and `dns`; GitHub #620), and it has the fixes of the black-box QA pass of 2026-11-26 (GitHub #761 to #775).

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text. `pod-report.schema.json` is the JSON
Schema of `podnet pod --report`. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.20` (also `:beta`).

## Breaking

Exit codes:

* A name that does not resolve exits 68 (`no-host`), as `podnet man exit-status` says (T-595, #763): `connect`,
  `relay connect`, `send`, `tunnel --transport relay` and each other command whose dns hop fails. Before, they exited
  69. A proxy host that does not resolve stays 69 (the proxy hop).
* A bad value of `--peer` (`link dial`, `link connect`, `forward` to a peer, `relay --seal`) exits 64 and names the
  value (T-599, #767). Before, it exited 78 and named "line 1".
* `init check` and the other readers of a node configuration exit 66 (`no-input`) for a missing file, and name the file
  first (T-607, #775). Before, they exited 78 with "the configuration is not schema 1".
* `pod --serve` stops cleanly at SIGINT, SIGTERM and SIGHUP: one line `SIGNAL: stopping`, its unix socket removed, exit
  0 (T-602, #770). Before, the signal killed it (130, 143) and the socket stayed.

Behaviour and output:

* `cover` with no `--name` serves its site to each name of the handshake, and to a handshake with no name (T-591).
  Before, each request got the 404 page, also `/`.
* `link p2p` sends the FIN to the peer at the end of stdin and reads the answer until the peer closes (T-592). Before,
  the end of stdin ended the command, and the answer was lost.
* `expose --via switch` with a `--switch` after `--` gives the stack the address of `--as` (T-605, #773).
* A proxy that answers 502 or 504 (a SOCKS5 refusal of the far side) is the connect hop, the target, in the error
  line (T-594, #762). Before, the line blamed the proxy and said to go around it.
* A timeout of a dial names its time limit (T-593, #761). Before, `connect`, `relay connect` and `send` said
  "timed out after 0s".
* A refused TCP bind names the step of its port (T-606, #774): above 1023, the host refuses the TCP listener (a unix
  socket); below 1024, a port above 1023.

## Changes for a tester

* The release binaries have the link carriers `tcp`, `ws`, `h2`, `quic`, `udp`, `poll` and `dns` (T-428, #620).
  `podnet link carriers` lists them.
* `net proxy --switch tcp://HOST:PORT` takes a name (T-596, #764), and the connect to the switch ends after 20 s with one
  line (T-600, #768).
* A network `NAME` of a router file reads its own TURN account from `PODNET_TURN_USER_NAME` and the other TURN
  variables with that suffix (T-321).
* The warning "DNS discovery of the edge failed" comes once at a start (T-601, #769).
* A command that reads stdin ends at once when it is done, also when stdin stays open (T-592).
* The crash log and `harness` name the tag of podcrates that the build takes (T-590).
* `wait --help` says exit 124 (T-597, #765); `offline` says an eight-word code (T-603, #771); `offline pair accept`
  asks for the code on a terminal, and its help names stdin (T-604, #772).
* Each command of a release binary but `net tailscale` has a scenario of the release gate (T-398).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`. The test guide is GitHub #89.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* Four findings of the QA passes wait for a tag of PodUtils/podcrates (`docs/decisions.md`, 2026-11-25):
  * A name that does not resolve gives a line cut inside a cause (T-575, #737; COORD-123).
  * Behind a proxy, `tunnel` can wait about 35 s in DNS over HTTPS with no line (T-579, #741; COORD-125).
  * `--proxy http+exec:` with a command that does not exist prints a line of `sh` for each try, and hides the
    command (T-580, #744; COORD-124).
  * On a host that refuses a TCP bind and has no IPv6, the TCP carrier rows of `doctor` name the IPv6 try, not the
    refused bind (T-598, #766; COORD-131).
* No crates.io release of `podnet` exists.
* Experimental (no scenario of the release binary): `podnet net tailscale`. Only the tests with stand-ins check it.
* The link carriers `icmp`, `s3`, `ntp`, `smtp`, `imap`, `ss` and `trojan`, the `sidecar` commands and the C interface
  are not in the release binaries (`docs/build.md`).
* The limits of v0.4.0-beta.13 stand.

## Known problems

* About one `live` run of six fails at the public relay: the relay keeps a lost socket of a node after a reset (T-406,
  PodUtils/podnet#604). At times, the door of WARP shows a certificate of Let's Encrypt (T-406); `live` then gives a
  warning (T-587).
* The quick-tunnel service refuses a busy runner with HTTP 429 (error 1015) at times; `live` then gives a warning
  (T-589).
* A quick tunnel gets HTTP 530 from the edge for some requests, at times (T-488).
* Two parallel SSH sessions through one relay node: one can hang (T-478).
