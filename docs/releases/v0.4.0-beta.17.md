A prerelease of `podnet`, for tests. It follows v0.4.0-beta.17. It is a beta of fixes for podrunner (PodUtils/podrunner#213, #142) and the fixes of the QA round of 2026-11-17 (GitHub #609 to #648).

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text. `pod-report.schema.json` is the JSON
Schema of `podnet pod --report`. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.17` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.17 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.17   # rebuild and compare (x86_64, aarch64)
```

`podnet update` does the first three checks itself.

## Breaking

* `podnet bench` exits 1 when no request passes; an HTTP error counts as a failed request. Before, it exited 0 when
  each request failed (T-463, GitHub #639).
* `podnet forward --dns` exits 69 when the DNS door cannot bind its address, and prints no ready line before the bind.
  Before, it printed the door as up and then exited 1 (T-462, GitHub #638).
* `podnet link`: the scheme of an address selects the carrier. `unix:PATH` is the `unix` carrier at `PATH`; before, the
  whole text was taken as a file name (T-458, GitHub #634).
* `podnet status` and the other one-shot commands print no INFO line on stderr at the default log level (T-437, T-468,
  GitHub #617, #644). A script that read that line must use `-v`.

## Changes for a tester

* `pod --backend seccomp` on a host that refuses writes to the memory of the program: a connect to a loopback port of
  the host gives the program a kernel TCP socket; a socket option that the program reads before `connect`
  (`IPV6_V6ONLY`) works. The .NET 8 `HttpClient` connects (T-456, PodUtils/podrunner#213).
* `pod --backend seccomp`: a program that waits with epoll (.NET, the GitHub runner) keeps its nonblocking socket on the
  relay; the second and later requests through a proxy on a Unix socket no longer time out (T-457,
  PodUtils/podrunner#142).
* `pod -x` with a dead upstream fails at once, not after a hang (T-430, GitHub #610); `pod -r 'cidr:...=reject'`
  refuses a name too (T-431, GitHub #611); `pod -x direct` prints no false warning (T-432, GitHub #621).
* `net proxy` gives an error, not a SOCKS5 success then EOF, for a target outside the virtual network (T-433, GitHub
  #609). `serve` answers a client that half-closes before the answer (T-434, GitHub #613).
* Each detached `--json` document has the keys `url`, `listen` and `listens`; the keys of a command stay (T-465, GitHub
  #641). `route --detach --json` prints its ready document (T-466, GitHub #642).
* `exit` serves stdio with no flag (T-438); `autostart run` takes the state directory as its default `--dir` (T-439);
  `forward --name` listens on the port of its target with no `--alias-port` (T-440); `autostart list --json` and
  `--manual` (T-445); `relay node --json` (T-446); `ssh-relay --run-for` and a quiet `-q` (T-447); `serve` adds a user
  to its users file (T-448); `serve --check --local` (T-467); `expose --via switch` takes an `http://` target (T-470).
* `ssh-relay` takes `--proxy`, `--egress`, `--resolve` and the proxy variables (T-474). `warp up` reads the six system
  CA bundles of `pod_tls` (T-475).
* Error lines name each cause once (T-459, GitHub #635). A refusal for now (HTTP 429, exit 75) says that a retry later
  can pass (T-477). `autostart add` that exits 69 leaves no entry (T-464).
* `serve`: a plain-HTTP listener sets no Secure cookie, so the PIN unlock stays (T-460); the output of `--pin` says how
  to unlock (T-443); the HTML listing has the modified time, the upload limit and the tar link (T-472, T-444).
* `route`: the usage file is in `state_dir` (T-427); a door quota is not overshot by a flow buffer (T-461).
* `podnet-install.sh` prints one proxy line for one proxy, and gives way to the next default directory when the first
  is on a noexec mount (T-469, GitHub #645).
* Each flag that a help names exists, each example of the manual parses, and each `--json` document has one schema:
  tests of the release binary in the gate (T-451).
* The shared crates of PodUtils/podcrates are at `v0.70.0` (T-480). The Cloudflare tunnel is the crate
  `pod-cloudflare` (T-423).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`. The test guide is GitHub #89.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* The release freeze of 2026-11-17 holds: this beta carries fixes only. The error-path rows of the lane (T-452), the
  lab of the testers' host class (T-453) and a black-box QA pass (T-454) are not done.
* No crates.io release of `podnet` exists.
* The Rekor inclusion proof is not checked by `podnet update`.
* Experimental (no scenario of the release binary): `podnet net tailscale`, `podnet ssh-relay` and `podnet warp license`.
  Only the tests with stand-ins check them.
* The release binaries have the link carriers `unix` and `memory` only (`docs/link.md`, T-428, GitHub #620).
* The limits of v0.4.0-beta.13 stand.

## Known problems

* About one `live` run of six fails at the public relay: the relay keeps a lost socket of a node after a reset (T-406,
  PodUtils/podnet#604). The fix is in the relay role of podssh; a relay of the pool keeps the fault until its operator
  deploys it.
* Two parallel SSH sessions through one relay node: one can hang (T-478).
