A prerelease of `podnet`, for tests. It follows v0.4.0-beta.9.

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text. `pod-report.schema.json` is the JSON
Schema of `podnet pod --report`. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.10` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.10 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.10   # rebuild and compare (x86_64, aarch64)
```

`podnet update` does the first three checks itself.

## Breaking

* A sealed stream of `podnet link dial` (`--seal`) that cannot resume (three
  refused RESUME records, or no new carrier in the window) exits 69
  (`ResumeExpired`). Before, the read error ended the dial with 0 (T-301).
* The WARP chain is the crate `pod-warp` (T-050, T-137). Its log lines have
  the target `pod_warp`: `RUST_LOG=podnet=debug` does not show them. Name
  both targets (`RUST_LOG=podnet=debug,pod_warp=debug`). The default filter
  of podnet names each `pod-*` crate that it runs (T-332).

## Changes for a tester

* `podnet send PATH` and `podnet receive`: a file, a directory or a text by a
  short code, through a mailbox of magic-wormhole (`docs/transfer.md`). The
  transit goes direct, through a transit relay, through the podnet relay
  (`--relay-pair NAME`) or through a piping server (`--piping URL`). A
  refused input exits 65 (T-102, T-104, T-105, T-251, T-252).
* `podnet link`:
  * New carriers (each a build feature, all in `full`): `quic`, `udp` (KCP;
    `?kcp-nodelay=1`), `poll`, `sse`, `chunked` and `httppoll`, `dns`
    (`--dns-zone`, `--dns-server`) and `icmp` (`--allow-raw icmp`, needs
    `CAP_NET_RAW`) (T-271 to T-273, T-276, T-278, T-280, T-282).
  * The keys from end to end: `--seal` gives an AEAD record layer over
    `pod-e2e`, with padding, compression, a replay window and RESUME. A
    middle node of the mesh sees records only (T-298 to T-301).
  * The ARQ under a link over a lossy datagram carrier (T-277).
  * `link connect --announce`: a node dials and serves, so three processes
    make a chain (T-287). Two next hops of one announcement give two routes;
    a stream fails over to the second (T-335).
  * The local SOCKS5 door of `link dial --listen`: `--resolve-at local`
    tries each address of a name (T-333).
* WARP: `warp` and `warp:identity=FILE` are networks of the registry: `podnet
  forward --network warp`, a member of a router group (health, egress check,
  renewal, `--rotate`, `--reconnect`) (T-057, T-061, T-095, T-097, T-099,
  T-180). `warp nc` over TCP with no `warp up` keeps its session (T-012).
* `podnet relay node --resume` and `relay connect --resume`: a session moves
  to a new leg before the limits of the relay and resumes after a lost leg
  (T-087).
* `podnet pod --backend netns-kernel`: the netns backend with netfilter in the
  namespace as its data plane; never chosen by `auto` (T-153).
* The shared crates of PodUtils/podcrates are at `v0.40.0` (T-137).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`. The test guide is GitHub #89.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* No crates.io release of `podnet` exists.
* The Rekor inclusion proof is not checked by `podnet update`.
* `rsa` 0.10.0-rc.18 (pinned by russh) has the advisory RUSTSEC-2023-0071, a timing
  leak of an RSA private key. podnet makes Ed25519 keys. Give podnet no RSA key (T-326).
* A file or a directory of `podnet send` goes to another podnet only: the
  transit key of magic-wormhole waits for `pod-wormhole` (T-103,
  PodUtils/podnet#535). A text needs no transit key. No test ran against the
  Python client (T-106).
* The carriers `quic`, `udp`, `dns` and `icmp` dial from a UDP or raw socket
  of the host: `--egress` does not apply to them.
* In a seccomp pod, a raw ICMP socket goes past the upstream (T-334,
  PodUtils/podnet#538).
* The limits of v0.4.0-beta.9 stand, except the carriers and the keys from
  end to end of `podnet link`, which this release adds.
