A prerelease of `podnet`, for tests. It follows v0.4.0-beta.15.

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text. `pod-report.schema.json` is the JSON
Schema of `podnet pod --report`. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.16` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.16 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.16   # rebuild and compare (x86_64, aarch64)
```

`podnet update` does the first three checks itself.

## Breaking

* `podnet relay connect` and the resume layer exit 69 (not 78) when a proxy or another hop on the way refuses the
  WebSocket upgrade with its own page: the message names the hop, not the connect token. A refusal of the relay itself
  (`reverse: forbidden`) is still exit 78 (T-421).

## Changes for a tester

* Each WebSocket and relay connection takes the roots of `--ca-file` or `SSL_CERT_FILE`, as the other clients of
  podnet do: `relay pair`, `relay node`, `relay connect`, `--resume`, the relay leg of a tunnel, `connect`, the
  WebSocket of `--url` and the Dev Tunnels network. Before, they used the system and compiled-in roots only, so a host
  behind a proxy that re-signs TLS could not reach the relay, also with the CA in `--ca-file` (T-421).
* The release gate has two new rows: `relay connect` through a proxy-only way out, and through a proxy that refuses
  the WebSocket upgrade (`podlab run --way-out ws-upgrade-refused`) (T-358).
* `cargo deny` ignores no advisory: russh 0.65.2 takes `rsa` 0.10.0, which fixes RUSTSEC-2023-0071 (T-326). The
  compiled-in roots are webpki-roots 1.0.12.
* The shared crates of PodUtils/podcrates are at `v0.68.0` (T-420).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`. The test guide is GitHub #89.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* No crates.io release of `podnet` exists.
* The Rekor inclusion proof is not checked by `podnet update`.
* Experimental (no scenario of the release binary): `podnet net tailscale`, `podnet ssh-relay` and `podnet warp license`.
  Only the tests with stand-ins check them.
* The netlink answer of the vnet shim was not measured with libtorrent or qBittorrent. A program that reads a netlink
  socket with `read(2)` after `write(2)` gets no answer.
* The limits of v0.4.0-beta.13 stand.

## Known problems

The QA round of 2026-11-17 found these after the tag. `main` has the fixes;
the next beta has them.

* GitHub #610 to #633: defects and usability faults of the CLI (exit codes,
  error texts, help, JSON output). Each is closed with its fix on `main`.
* GitHub #634 to #648: in work.
* GitHub #620: release binaries have the link carriers `unix` and `memory`
  only (`docs/link.md`).
* PodUtils/podrunner#213 (T-456): under `pod --backend seccomp` on a host
  that refuses writes to the memory of the program, a socket option that
  the program reads before `connect` (`IPV6_V6ONLY`) fails with
  `EOPNOTSUPP`. A .NET program (the GitHub runner) fails. Use
  `--backend netns` where it works. In work.
* PodUtils/podrunner#142 (T-457): a program that waits with epoll (.NET)
  timed out on its second request through a proxy on a Unix socket. Fixed
  on `main`.
