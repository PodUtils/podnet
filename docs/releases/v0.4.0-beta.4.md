A prerelease of `podnet`, for tests. It follows v0.4.0-beta.3.

A user of `cfrs` reads the notes of v0.4.0-beta.1 first. They give the
rename and the move from `cfrs`.

## Binaries

| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text (T-222). `SHA256SUMS` lists each
file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.4` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.4 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.4   # rebuild and compare (x86_64, aarch64)
```

`podnet update` does the first three checks itself.

## Breaking

A command or a script written for v0.4.0-beta.3 must change for each item
below.

1. `podnet pod -r` stops with exit 64 when an earlier rule shadows a later
   `reject` rule. Give `--allow-shadowed-rules` to keep the old order. A rules
   file of the router with such a rule does not load. A shadowed rule of
   another action gives a warning only (T-242).
2. `scripts/install.sh` stops before each download when the tag is not a
   release tag, or when `PODNET_REPO` is not `OWNER/NAME`. `install.sh` and
   `podnet update` need exactly one valid line of `SHA256SUMS` for the file
   (T-239).
3. `warp`: a registration `POST` that got an HTTP answer (a 5xx too) is not
   sent to the second API host. The identity file can hold a device with
   `state: "created"` after a kill; the next run finishes it with a `PATCH`
   and makes no new device. A second registration of one identity file waits
   for the lock, and stops with exit 75 after 60 s (T-241).
4. `warp tun --default-route`: a second `warp tun` on one state directory
   stops with "another warp tun runs". The new `resolv.conf` has the mode of
   the old file (0644 for a new file), not the mode of the umask (T-240).
5. The netns backend makes a veth pair when the namespace cannot open
   `/dev/net/tun`. Before, the pod stopped there (T-174).

`doctor --json` is schema 1 with a fixed key set: keys are only added. It has
the new keys `quick` and `lanes` (T-216, T-217). `docs/protocol.md` section 9
lists each key; section 10 is the connector profile (T-218).

## Changes for a tester

The router:

* `podnet route --config FILE`: a YAML file of `networks`, `groups`,
  `policies`, `health`, `control` and `doors`. Each door is a SOCKS5 and HTTP
  CONNECT door on TCP or `unix:`, over a network, a group or a rules file. A
  door can have a DNS door (`dns`, `dns_upstream`). `--detach --name N` and
  `autostart add` take it (T-100, T-098).
* `route --check --to HOST:PORT [--door N]`: a dry run that prints the rule,
  the way and the member of each door, with no dial (T-177).
* `route --status unix:/PATH [--json]`: the state of a running router from
  its control socket: each group, the health, the round-trip time and its
  floor, the flows, the bytes and the head (T-097, T-178).
* The key `kernel` of the router file writes policy routing with no `ip`
  program: a table, a default route and an fwmark rule for each WAN, and a
  weighted multipath route; it needs CAP_NET_ADMIN (T-119). The keys
  `masquerade`, `mss_clamp`, `kill_switch` and `rp_filter` (each on by
  default) add a masquerade and an MSS clamp through nf_tables, an
  unreachable route when each WAN is down, and rp_filter 0 on each WAN
  (T-120).
  `route --config FILE --export mwan-json` prints the WANs in the JSON form
  of the mwan director (T-121).
* `health` takes `down_after`, `up_after`, `cooldown`, `timeout` and
  `window` (T-097, T-178). `policies` takes `weighted`, `rr`, `minrtt`,
  `leastload` and `protect` (T-178).

Fixes:

* The tests that need a namespace, a loopback or a TUN skip on hosts that
  do not allow them (GitHub runners): the veth wire, the register tests of
  WARP, the kernel mode of the router.
* Each probe child of `pod doctor` closes the descriptors that it inherits.

Forwards and tools:

* `podnet forward -L udp:LISTEN=HOST:PORT` over the datagrams of a network,
  and `--dns ADDR:PORT --dns-upstream HOST:PORT` (T-099).
* `podnet expose TARGET --via tunnel|relay|switch` (T-099).
* `podnet bench URL [--json]`: requests, errors, rate and latency over the
  way out (T-221).
* The network `netbird:[PORT]` (default 1080) dials an address through the
  SOCKS5 listener of NetBird in netstack mode; a name target fails, as that
  mode has no DNS. `net doctor` has a row for the listener (T-246).
* NetBird, Firezone and ZeroTier are studied as networks
  (`docs/research/podnet/overlays.md`, T-118).
* `--help --json` on each command prints the manual of that command as JSON
  (T-222).

Overlays:

* `net tailscale --tailnet NAME` (or `PODNET_TAILNET`) opens the door only
  when `tailscaled` is `Running` in that tailnet: exit 78 in another
  tailnet, exit 69 when the daemon is not ready. `net doctor` has a row for
  `tailscaled` (T-243).

Library and crates:

* `warp` (the WireGuard leg): the handshake, the cookie, the session and
  the timers are the crate `pod-wg` of podcrates. It fixes these defects:
  a bad response reset the times of a rekey; the age of a session was read
  from the system clock; a TAI64N timestamp could go back or repeat; a
  responder under load refused each handshake (no mac2 of a cookie); a
  failure of the random bytes was a panic. The keys are wiped on drop
  (T-137).
* podnet takes the crates of `PodUtils/podcrates` at v0.22.0. The
  measurement of the edge of Cloudflare's tunnels moved to
  `PodUtils/podcrates:scripts/services/edge-facts.sh` (T-137).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* No crates.io release of `podnet` exists.
* The Rekor inclusion proof is not checked by `podnet update`.
* `warp --cc reno|cubic` is slow on a link that gives one ACK for each round
  trip (smoltcp 0.14; PodUtils/podcrates#66). Keep the default (no
  controller).
* The door of the router has no UDP ASSOCIATE (T-098). The byte meter of a
  member counts TCP flows only, not UDP datagrams (T-178).
* `warp forward` is not yet an alias of `podnet forward` (T-099).
