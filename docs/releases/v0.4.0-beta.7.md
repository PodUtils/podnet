A prerelease of `podnet`, for tests. It follows v0.4.0-beta.6.

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.7` (also `:beta`).

## Check a download

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify podnet-x86_64-unknown-linux-musl --repo PodUtils/podnet
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/PodUtils/podnet/.github/workflows/release.yml@refs/tags/v0.4.0-beta.7 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sh scripts/rebuild.sh v0.4.0-beta.7   # rebuild and compare (x86_64, aarch64)
```

`podnet update` does the first three checks itself.

## Breaking

* `podnet relay` runs on `pod-relay` of podcrates (T-049). A pair file is
  `relay/pair-NAME.json`; an old `relay/NAME.json` is not read: make a new
  pair with `podnet relay pair` after the update.
* `podnet relay node`: a node whose name another node holds exits 69 after
  30 s. Before, it connected again with no end.
* `podnet relay node`: a Close 1008 with "token" does not stop a node; a 401
  or 403 of its upgrade does.
* `podnet relay connect`: a bad pair name exits 64.

## Changes for a tester

* `podnet relay`: a relay host that stalled or failed is tried last on the
  next connect, for 10 minutes; a success brings it back (T-162).
* `podnet relay`: the budget of a stream follows the `limits` that the relay
  publishes in its pool document (T-163).
* The library: a relay node can serve an in-process handler, with no socket
  file (`relay_reverse::run_node_with`, `channel`) (T-083).
* `podnet relay connect`: each byte of the node reaches stdout at once. An
  `ssh` through `ProxyCommand` no longer waits for sshd to end the session
  (T-315).
* The tests: a local stand-in of the quick-tunnel service and of the HTTP/2
  edge runs the quick tunnel in `ci`, with no call to Cloudflare (T-316).
* podnet takes the crates of `PodUtils/podcrates` at v0.31.0 (T-137).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`. The test guide is GitHub #89.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* No crates.io release of `podnet` exists.
* The Rekor inclusion proof is not checked by `podnet update`.
* Not measured against a live relay: the order of the hosts after a stall,
  and the budget from the published limits.
* The limits of v0.4.0-beta.6 stand.
