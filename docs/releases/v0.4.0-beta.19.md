A prerelease of `podnet`, for tests. It follows v0.4.0-beta.18. It has the fixes of the black-box QA pass of 2026-11-25 (GitHub #713 to #751), temp paths with a random name, and the shared crates of PodUtils/podcrates at `v0.84.0`.

## Binaries

| File | System |
| --- | --- |
| `podnet-x86_64-unknown-linux-musl` | Linux x86-64 |
| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |
| `podnet-armv7-unknown-linux-musleabihf` | Linux ARMv7 (32-bit, hard float) |
| `podnet-arm-unknown-linux-musleabihf` | Linux ARMv6 (32-bit, hard float) |
| `podnet-i686-unknown-linux-musl` | Linux x86 (32-bit) |
| `podnet-riscv64gc-unknown-linux-musl` | Linux RISC-V 64 |
| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text. `pod-report.schema.json` is the JSON
Schema of `podnet pod --report`. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.19` (also `:beta`).

## Breaking

`podnet pod`:

* The egress policy of the process (`PODNET_POLICY`, `PODNET_NODE_CONFIG`) applies to each flow of the program and
  of `--serve`, before the rules of `-r` (T-572). A destination that the policy refuses gets the answer of a
  `reject` rule: `ECONNREFUSED` (netns: a reset), SOCKS5 `0x02`, HTTP 403. Before, the pod did not ask the policy.
* `--backend netns` and `--backend netns-kernel` run the probe of `auto` before the start (T-578). A host where the
  backend cannot run gives one line with the cause and the step, and exit 3.
* `pod doctor` gives the verdict of the start of each backend (T-547, T-581): the row "TCP connect (127.0.0.1)" and
  the row "write the id maps (NEWUSER)" are new. A host where a TCP connect, the id maps or the read of the memory of
  a program is refused gives `fail`, and exit 3 when no backend can run. Before, it gave `ok`.
* `pod-report.schema.json` takes the backend `netns-kernel` (T-577).

Exit codes:

* `warp status`, `rotate`, `delete` and `license` exit 66 (no-input) when the identity file is absent (T-574). Before,
  they exited 78.
* A TCP listener on a loopback address that no connect reaches (a host with no address on `lo`) exits 69 with the
  step (T-564): `serve --local`, `git serve --local`, `share --local`, `forward -L`, `connect -L`, and each `--listen
  tcp://`. `serve --check` fails the row. Before, the listener was ready and no client connected.
* `route --config` with a missing or bad file exits 78 (T-567). Before, it exited 64.
* A crate failure of the class Data (podcrates `v0.84.0`) exits 65.
* `exit`: a name with no address and a dial time limit get the SOCKS5 reply `0x04` (T-554); a closed virtual port of
  `net proxy` gets `0x05` (T-555).

Output:

* Each JSON event of `tunnel`, `send`, `receive`, `relay`, `offline`, `host probe` and `stat --json` has `schema` 1
  (a number) and the key `podnet` (T-551, T-558). `send --json` gives the bytes of a text in its `sent` event (T-584).
* `podnet doctor` has the row `nat`: the class of the NAT of the host by `pod-natprobe` (T-543). It does not change
  `ok`.
* The error line of a refusal of the policy names the rule and the file (`podnet rules check FILE`), not the step of a
  connect hop (T-573). `update --check` stops after a failure of the proxy hop (T-582). `warp up` says each cause of a
  failure once (T-576).

## Changes for a tester

* Temp files and sockets have a random name, not the pid (T-545): two processes in two PID namespaces do not meet on
  one path.
* `logs` holds the lines that a detached start shows before its ready (T-548).
* `doctor` and `warp proxy` name the class of the certificate of a MASQUE door (T-549, T-553); `pod-warp` says the
  cause once (COORD-121).
* A client of `warp proxy` with no WARP session gets the SOCKS5 reply 1 or HTTP 503, not a reset (COORD-120).
* `init enroll`, `wg serve`, `autostart add`, `offline bundle build`, `rules check`, `ci check`, `man --json`,
  `--egress`, `forward` (UDP over the way of the process) and `--log-format json`: the fixes of T-556, T-557, T-559 to
  T-563, T-565, T-566, T-568 to T-571.

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`. The test guide is GitHub #89.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* Three findings of the QA pass wait for a tag of PodUtils/podcrates (`docs/decisions.md`, 2026-11-25):
  * A name that does not resolve gives a line cut inside a cause (T-575, #737; COORD-123).
  * Behind a proxy, `tunnel` can wait about 35 s in DNS over HTTPS with no line (T-579, #741; COORD-125).
  * `--proxy http+exec:` with a command that does not exist prints a line of `sh` for each try, and hides the
    command (T-580, #744; COORD-124).
* No crates.io release of `podnet` exists.
* Experimental (no scenario of the release binary): `podnet net tailscale`, `podnet ssh-relay` and `podnet warp license`.
  Only the tests with stand-ins check them.
* The release binaries have the link carriers `unix`, `memory`, `serial` and `hf` only (`docs/link.md`, T-428, GitHub
  #620).
* The limits of v0.4.0-beta.13 stand.

## Known problems

* About one `live` run of six fails at the public relay: the relay keeps a lost socket of a node after a reset (T-406,
  PodUtils/podnet#604). At times, the door of WARP shows a certificate of Let's Encrypt (T-406, live 45589043028).
* The quick-tunnel service refuses a busy runner with HTTP 429 (error 1015) at times (live 45616517699).
* A quick tunnel gets HTTP 530 from the edge for some requests, at times (T-488).
* Two parallel SSH sessions through one relay node: one can hang (T-478).
