A prerelease of `podnet`, for tests. It follows v0.4.0-beta.20. It takes PodUtils/podcrates `v0.86.0`; its release binaries have each carrier of the link; it adds new roads (the networks `https://`, `wstunnel:`, `vless://`, `ss://` and `wisp:`, the DERP road, ACME for a public listener, the TCP direction split of a router group, the inspector of a tunnel), and it has the fixes of the documented commands and of the QA pass on restricted hosts.

| `podnet-aarch64-unknown-linux-musl` | Linux ARM64 |

| `podnet-loongarch64-unknown-linux-musl` | Linux LoongArch64 |
| `podnet-powerpc64le-unknown-linux-musl` | Linux POWER, little-endian |

Each binary is static (musl). It needs no C library on the host.
`podnet.1` is the manual page. `llms.txt` and `llms-full.txt` are the
manual and the documents as plain text. `pod-report.schema.json` is the JSON
Schema of `podnet pod --report`. `SHA256SUMS` lists each file.

The image is `ghcr.io/podutils/podnet:v0.4.0-beta.21` (also `:beta`).

## Breaking

* `tunnel --inspect` is the inspector of the HTTP exchanges (T-244, #435). The hop table of the end-to-end session
  moves to `--e2e-inspect`; `--inspect` with no origin exits 64 and names `--e2e-inspect`.
* A network spec `https://HOST:PORT` is a TLS connection to an HTTP proxy (T-126). Before, `https://` was refused.
* `offline announce` on a host with no UDP exits 69 with the step and the address (T-615). Before, it exited 1.
* A refused remove of a stale Unix socket (another user's socket) exits 69 and says to give another path (T-616).
  Before, it exited 1.
* `offline spool take --out FILE` with FILE present exits 64, and the entry stays in the spool (T-613). Before, 65.
* The reason of a policy refusal says "the rule NAME refuses the destination" and "so the policy refuses it" (T-617).
  Before, "refuse".
* With `--ca-file` or `SSL_CERT_FILE`, the hint of an unknown issuer names that file, not `podnet-ca.pem` (T-618).
* `stat --peer NAME:PORT` exits 68 when NAME does not resolve (T-622, #788). Before, it exited 1.
* `ssh-relay` exits 68 (unresolved host) or 69 (unreachable or silent relay/proxy) when the first start fails, with no
  retry loop; reconnect backoff applies after a session has started (T-624, #790).
* `relay connect` and the other pair-name commands refuse upper-case letters locally with exit 64 (T-626, #792).
  Before, the relay refused them with exit 69.
* `warp` identity files with a loose mode or another owner exit 71 (`os-error`), matching `man exit-status` (T-630,
  #796). Before, they exited 78.

## Changes for a tester

* podnet takes podcrates `v0.86.0` (T-612): a name that does not resolve gives one line (T-575, #737); `tunnel` behind
  a proxy gives a line in DNS over HTTPS (T-579, #741); `--proxy http+exec:` hides the words of the command and says
  its status once (T-580, #744); the TCP carrier rows of `doctor` name the refused bind (T-598, #766).
* The release binaries have each carrier of the link: `s3`, `icmp`, `ntp`, `smtp` and `imap` join (T-609).
* New networks of `forward --network`, a router and a chain (`docs/networks.md`): `https://` (an HTTP proxy over TLS)
  and `wstunnel:` (T-126); `vless://` (VLESS over WebSocket or XHTTP), `ss://` (Shadowsocks, AEAD and 2022) and `wisp:`
  (Wisp over a WebSocket) (T-127). Each secret comes from a variable or a file, never from the spec.
* The DERP road (T-128; `docs/relay.md`, `docs/transfer.md`): `podnet derp node` and `podnet derp connect TICKET`, `podnet
  send --derp`, and the row `derp` of `podnet doctor` (`--derp-server LIST`).
* `serve` and `git serve` take `--acme DOMAIN --listen tcp://ADDR:PORT`: HTTPS with a certificate of an ACME CA, by
  TLS-ALPN-01 on the same listener (T-129; `docs/serve.md`). The account has no contact email yet (COORD-135, #780).
* `tunnel --inspect` keeps the last HTTP exchanges in memory with each secret redacted; `tunnel inspect list`, `show`,
  `replay` and `clear` read them over a socket of mode 0600 (T-244, #435; `docs/tunnels.md`).
* `splits:` of a router file takes `tcp=FINGERPRINT@UP|DOWN`: the TCP flows of a group go over a split session of the
  link (T-611, #375; `docs/router.md`).
* `podnet pod` removes its inbound sockets and their directory at its end, also after SIGINT, SIGTERM and SIGHUP, and
  a stale socket at the next start (T-619, PodUtils/podrunner#369).
* `net proxy` and `net switch` remove their Unix socket at a clean stop (T-616).
* A `podnet-ca.pem` beside the binary that a CA file keeps from being read gives one warning line (T-618).
* `link carriers` says the cost class once (T-610).
* The release gate runs the documented commands (the class `scenario` in the labs, the classes `live` and `root` in
  `live.yml`), real servers for each new road (coturn, Pebble, ssserver, Xray-core, wisp-server-python, derper), and the
  rows of the lane on an IPv6-only host (T-358).
* Fixes from the black-box QA pass of `v0.4.0-beta.21` (#786 to #798):
  * Unknown commands and flags no longer promise that a newer release knows them; typing mistakes keep clap's
    suggestion and other unknown words point to `podnet --help` (T-620, #786).
  * `exit --stdio` shuts down the write side of the target when stdin closes and ends cleanly with exit 0 if the target
    stays silent (T-621, #787).
  * `stat` resolves peers through the shared resolver path (pins and DNS over HTTPS) and exits 68 with `--resolve
    HOST=IP` on lookup failure (T-622, #788).
  * `derp node` stops after the first unreachable-proxy failure and groups repeated server errors by cause (T-623,
    #789).
  * `ssh-relay` exits 68 or 69 on first-start failure and bounds silent relays with a handshake timeout (T-624, #790).
  * A silent TLS peer after TCP connect maps to one hop (`tls-timeout`) and one hint across `connect`, `bench` and
    `relay connect` (T-625, #791).
  * `relay connect` and the other pair-name commands refuse upper-case letters locally with exit 64 (T-626, #792).
  * `serve --add-user` and `--replace-user` write no foreground-server notice (T-627, #793).
  * The upload example in `docs/serve.md` creates `share/inbox` and adds `bob:write` so it runs as written (T-628,
    #794).
  * A proxy CONNECT refusal (403/407) names the proxy and the target (`the proxy X refused CONNECT to HOST:PORT with
    HTTP STATUS`) with a port allow-list or auth hint across `connect`, `relay connect`, `send` and `bench` (T-629,
    #795).
  * WARP identity files with a loose mode or another owner exit 71 (`os-error`), and `docs/warp.md` agrees (T-630,
    #796).
  * `warp proxy --rule` help and `docs/warp.md` document all four rule kinds: `domain`, `cidr`, `port` and `tcp`
    (T-631, #797).
  * `podnet --log-format json pod` emits every `podnet pod:` stderr line as one JSON object, with `exit_code` on final
    errors (T-632, #798).

## What to report

Open an issue in `PodUtils/podnet` with the output of `podnet doctor --json`
and `podnet pod doctor --json`, the command, and the stderr of the command
with `-v`. The test guide is GitHub #89.

## Limits

* This is a beta. Each item of Breaking can change again before the stable
  release.
* The proxy of the process (`--proxy https://`, `HTTPS_PROXY=https://`) is refused; it waits for a TLS hop of
  `pod-proxy` (T-614, COORD-134 #779). The network `https://` of `forward --network` and of a router works.
* A Trojan service at a peer waits for a parser of a Trojan request in `pod-egress` (T-295, COORD-140 #785).
* No crates.io release of `podnet` exists.
* Experimental (no scenario of the release binary): `podnet net tailscale`, and `podnet tunnel inspect list`, `show`,
  `replay` and `clear`. Only the tests with stand-ins check them.
* The services `ss` and `trojan` of a link end, the `sidecar` commands and the C interface are not in the release
  binaries (`docs/build.md`).
* The limits of v0.4.0-beta.13 stand.

## Known problems

* About one `live` run of six fails at the public relay: the relay keeps a lost socket of a node after a reset (T-406,
  PodUtils/podnet#604). At times, the door of WARP shows a certificate of Let's Encrypt (T-406); `live` then gives a
  warning (T-587).
* The quick-tunnel service refuses a busy runner with HTTP 429 (error 1015) at times; `live` then gives a warning
  (T-589).
* A quick tunnel gets HTTP 530 from the edge for some requests, at times (T-488).
* Two parallel SSH sessions through one relay node: one can hang (T-478).
